## Boundaries

The local Obsidian research/curation product can be tested with user-supplied observations and public permitted RSS/Atom feeds. The ORIGINAL autonomous X "For You" → Obsidian promise is incomplete without a provider-authorized connector. No alternative feed is mislabeled as personalized X recommendations.

Visual aesthetics, accessibility and comparative quality are not established with certainty by metadata. A human must approve candidates. Social platform rules are not bypassed, and generated/user-edited notes are never silently conflated.

## Actual user acceptance checklist

1. Install the latest verified release in a duplicate or test vault using Obsidian Desktop 1.9.2+ and Node.js 22.16+.
2. Enable the Bases core plugin and X Feed Scraper; check Diagnostics for SQLite integrity, engine startup and References.md.
3. Import two posts mentioning the same link; verify a single source with two post relations.
4. Optionally enable public metadata enrichment; verify that quality changes update only unmodified generated notes.
5. Approve a candidate; explicitly add it to References.md and verify both the timestamped backup and preservation of every older entry.
6. Open Sources.base and search generated notes through the existing Obsidian MCP.
7. Restart Obsidian and verify persistence, correct statuses and no duplicate collector processes.
8. For RSS, configure a permitted public feed with a respectful interval, review run history and keep source identity separate from X.

The external provider blocker is tracked at https://github.com/ibbuilds/obsidian-x-feed-scraper/issues/2.
