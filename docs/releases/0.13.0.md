# Source Scraper v0.13.0 Beta 1 — faster JSON equality and keyword evaluation

Source Scraper stays **CLI-first and JSON/NDJSON-first**, without a required graphical interface or Obsidian installation. The public `schemaVersion: 1` JSON contracts, SQLite identities, human reviews, source provenance and change/alert semantics remain unchanged.

## Performance improvements

- **Linear JSON equality:** replace recursive object-key sorting and stringification with a direct, allocation-light structural comparison. Object key order remains irrelevant, array order remains significant, and missing fields are distinct from explicit null. Deep nested change paths and watch-rule behavior are unchanged.
- **Keyword filtering:** cache normalized/lowercase inclusion and exclusion terms per collection signal and project policy. A lightweight primitive-element comparison detects *in-place policy mutations* without serializing or deduplicating every term for every entity. Invalid terms still fail validation, and confidence and scores are unchanged.
- **Bounded offline reprocessing memory:** consume the SQLite entity statement as a streaming iterator instead of loading every retained entity row into an intermediate JavaScript array. Existing bounded 100-entity assessment commits and cancellation/failure boundaries remain in effect.
- Regression tests include 1,000 deterministic canonical JSON comparisons against the earlier implementation; escaped pointers, atomic arrays and currency guards; in-run filter mutations, duplicate keywords, exclusions, malformed policies and isolation; existing source, migration and Desktop Obsidian tests.

## Reproducible benchmark

The dedicated [performance CI comparison](https://github.com/ibbuilds/source-scraper/blob/v0.13.0-beta.1/.github/workflows/performance.yml) tests against the immutable v0.12 commit `939c7c7314db15b709d5c0713571b3a35e82ef37`, using synthetic inputs on the **same Linux runner**. One measured run found:

| Test | v0.12 | Candidate | Relative gain |
| --- | ---: | ---: | ---: |
| 16,000 equal nested JSON comparisons | 7,146.73 ms | 465.63 ms | 15.3× |
| 16,000 different nested JSON comparisons | 7,100.44 ms | 484.77 ms | 14.6× |
| 16,000 nested diff operations | 21,431.78 ms | 1,654.39 ms | 13.0× |
| 65,000 keyword assessments with 60 criteria | 730.25 ms | 511.79 ms | 1.43× |

These results are synthetic measurements of hot paths, **not claims that the entire engine or external HTTP/MCP scraping is 15× faster**. The benchmark gates reject significant regressions on SQLite reads, JSON input paging, unchanged snapshot replay, first ingest, and offline reprocessing.

## Distribution and release policy

This is the **sole GitHub Release** when the publishing workflow completes. The publisher first creates and verifies this new release, including its commit and all three assets; only then does it delete previous Releases. Historical Git tags/commits remain available for audit.

- `source-scraper.mjs`: main, bundled Node.js 22.16+ CLI.
- `source-scraper-0.13.0.tgz`: locally installable npm package, not published to npm registry.
- `obsidian-x-feed-scraper.zip`: separate optional Obsidian plugin, retaining installation ID `x-feed-scraper`.

## Quick start

```sh
node source-scraper.mjs init --dir ./demo
node source-scraper.mjs run --config ./demo/project.json
node source-scraper.mjs export --config ./demo/project.json --out ./results.json
```

The sample is local and synthetic. It does not contact X or another provider, and it does not write into an Obsidian vault.

## Unresolved external limitations

There is still **no verified provider-authorized connector** for a user's account-personalized X **For You** algorithmic feed. Actual owner-device vault/MCP acceptance is separate from automated isolated Desktop Obsidian tests. Scores and licensing remain evidence-dependent heuristics, and trusted local MCP servers/extensions are not OS-sandboxed.
