# Discovery Engine 0.9.0 Beta 1

This release completes the source-integrity and curation work following 0.8 and adds explicitly enabled delivery of watch alerts.

## Changes

- Independent caches per collection run, including when callers share cancellation signals; cancelled pages cannot commit late results.
- Conservative Product/Offer selection and rejection of HTTPS-to-HTTP redirects.
- Full observations and original entity drafts retained for faithful offline reevaluation, with additive recovery from existing immutable revisions.
- Current per-mention assessments replace historical maximum scoring; changed or excluded evidence can lower an automatic assessment without changing human decisions.
- Superseded mentions remain historical while their old scores stop contributing to current relevance. Missing snapshot records still do not imply closure or deletion, and isolated evaluator/processor inputs preserve original source evidence.
- Stable opt-in entity namespaces, safe defaults for new guided projects, and rejection of cross-source legacy identity collisions.
- Trimmed, case-insensitively deduplicated keyword policies; blank terms fail explicitly.
- Opt-in HTTPS webhook alerts with a durable delivery ledger, bounded retries, stable idempotency keys and status in Obsidian, the CLI and authenticated local API.
- Migration, webhook setup, curation acceptance and extension-isolation design documentation.

## Installation and compatibility

Extract `main.js`, `manifest.json` and `styles.css` into the existing `.obsidian/plugins/x-feed-scraper/` folder. The visible plugin is Discovery Engine; its ID and ZIP filename remain compatible. Requires Node.js 22.16+ and Obsidian Desktop 1.9.2+.

Back up the local database and vault before upgrading. Existing keys, reviews, source history, cursors and edited Markdown remain protected. Read [the 0.9 migration guide](https://github.com/ibbuilds/obsidian-x-feed-scraper/blob/v0.9.0-beta.1/docs/migration-v0.9.md) for keyword validation, legacy replay limits and namespace configuration.

The release workflow publishes only after the main-branch CI passes the Linux, macOS, Windows and isolated actual Obsidian Desktop jobs, and rechecks types, tests, production dependencies and the installable package before publication.

## Remaining external acceptance

The account-personalized X For You feed remains unavailable: an authorized endpoint/provider returning that ranking and a real permissioned read are still required. The owner's actual Obsidian vault and MCP installation have not been validated by the synthetic CI environment.

External webhook delivery is opt-in. Receiver-side idempotency is required for duplicate-safe processing across crashes or lost responses. Extensions and MCP executables remain explicitly trusted local code; the release does not claim an OS security sandbox or a universal license/quality verifier.
