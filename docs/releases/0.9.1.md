# Discovery Engine 0.9.1 Beta 1 — pre-acceptance hotfix

This release fixes two concrete pre-installation defects found while auditing 0.9.0 beta. It changes no saved entity identities, database schemas or human review decisions.

## Fixes

- Replace the green-but-empty Windows CLI smoke check. Earlier Windows logs showed `Set --feed or --fixture` and an empty database, while CI still passed. CI now executes the collector directly with Node and asserts actual fixture observations, source and link counts, an idempotent second import, persisted generic project entities, an error exit on invalid input, and the absence of unexpected fallback databases. It runs on Linux, macOS and Windows.
- Restrict automatic HTTP retrieval from all X and Twitter subdomains and fully qualified trailing-dot hostname equivalents, as well as `t.co` variants. Previously only bare and `www` X hostnames (and literal `t.co`) were denied. The rejection happens before DNS lookup and any network request. The X `t.co` URLs seen inside observations may still be saved as unresolved links; they are not automatically fetched.
- Route the global Obsidian **Sync configured source or research project** command to `/project/sync` when a generic research project is selected. The real Obsidian Desktop suite now exercises that command, rather than relying only on the sidebar button.
- Return a nonzero CLI exit status for partial legacy ingest or public-metadata enrichment failures. The smoke test deliberately processes a valid and an invalid post, confirms the valid row remains saved, and verifies the process fails and the run is marked partial.
- Check package and plugin versions for agreement rather than hard-coding the previous patch version in packaging tests.

## Installation and acceptance

Download `obsidian-x-feed-scraper.zip` from this release. Back up the vault and local SQLite data first; install the contained `main.js`, `manifest.json` and `styles.css` in `.obsidian/plugins/x-feed-scraper/` and restart or reload the plugin. Requires Obsidian Desktop 1.9.2+ and Node.js 22.16+.

For an acceptance checklist with expected outcomes, see [pre-installation checklist](https://github.com/ibbuilds/obsidian-x-feed-scraper/blob/v0.9.1-beta.1/docs/preflight-v0.9.1.md). The core local engine, migration, Obsidian reviews and opt-in webhook configuration remain as in 0.9.0.

## Remaining external blockers

- The personalized X **For You** ranking is still not available from a verified, authorized source; the blocked adapter has **not** been replaced by Following/search/RSS.
- The owner must still validate the ZIP in their *own* Obsidian vault and connected MCP environment. CI tests use synthetic data in an isolated vault and do not authorize a personal installation.
- Webhook tests are mocked, not deliveries to a real receiver; destination, receiver-side idempotency, permissions and network behavior require live acceptance before enabling them.
- The engine uses heuristics for relevance/licensing, and trusted local extensions/MCP executable code is not operating-system sandboxed.
