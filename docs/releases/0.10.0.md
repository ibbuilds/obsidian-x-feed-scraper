# Source Scraper 0.10.0 Beta 1 — JSON-first general-purpose data engine

The **main product is now a standalone, local-first JSON/NDJSON CLI**, not an Obsidian plugin. The existing engine, source adapters, evaluator, evidence/deduplication store and SDK are retained. Obsidian remains a separately packaged, optional integration for existing users.

## Install without npm, build tools or Obsidian

1. Download `source-scraper.mjs` from this release.
2. Install Node.js **22.16+**.
3. Run `node source-scraper.mjs init --dir ./demo`, then `node source-scraper.mjs run --config ./demo/project.json`.
4. Run `node source-scraper.mjs export --config ./demo/project.json --out ./results.json` or use `--format ndjson`.

The example is entirely offline and synthetic. It creates a JSON input file and JSON project manifest; the database is created only when collection runs.

## Included assets

- **`source-scraper.mjs` — main product:** self-contained Node ESM bundle with required npm dependencies included. No Obsidian runtime, npm install or repository checkout required.
- **`source-scraper-0.10.0.tgz` — alternate npm-installable CLI package:** install from this release, not from the npm registry; `bin/source-scraper` resolves to the bundled executable.
- **`obsidian-x-feed-scraper.zip` — optional compatibility plugin:** existing plugin ID `x-feed-scraper` retained. Requires Obsidian Desktop and Node. It is not the default way to operate Source Scraper.

## CLI

Commands `init`, `validate`, `run`, `projects`, `query`, `inspect`, `review`, `reprocess`, `export`, `adapters`, `version`.

- Machine-readable JSON stdout by default, NDJSON on explicit `export --format ndjson`.
- Versioned project, observation, JSON-export and NDJSON-line schemas in `schemas/` (`schemaVersion:1`).
- A complete, inspectable information path: source observations, normalized entities, evidence, human review, assessment history, and change/alert data.
- Default SQLite lives beside the manifest as `.source-scraper.sqlite`; stored records are separated by project. Query commands refuse absent databases rather than silently invent empty successes.
- Exports are create-only to prevent overwriting existing user files; `--out` writes JSON and returns a receipt. No OutputAdapter/webhook side effects during normal `run` or `export`.
- Safe offline demo and isolated single-file smoke tests; no direct network calls needed.
- Core unit tests plus Linux/macOS/Windows bundled CLI execution and actual Obsidian Desktop E2E for the optional plugin.

## Design limitations and compatibility

- **No verified authorized X personalized For You adapter.** Public APIs, RSS, Following/search/Bookmarks or manually supplied observations do not prove access to the account's algorithmically ranked For You timeline. Do not scrape cookies or bypass provider controls.
- SQLite schema migrations remain additive; retained reviews and existing entity IDs preserved. Back up the local database before upgrade.
- Source-specific quality and license assessment remain heuristics based on evidence and user configuration; the engine does not invent official licenses or URLs.
- Trusted local MCP/executable extensions still execute as the OS user. No OS sandbox is claimed.
- Existing Obsidian plugin can still be installed separately. The workspace remains in the same repository for compatibility and has **not** been moved to a distinct GitHub repo.
- The npm `.tgz` is locally installable from the release but the project is **not published on npm**.
