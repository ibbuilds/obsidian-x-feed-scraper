# Source Scraper 0.12.0 Beta 1 — safer repeat processing and faster offline replay

This is a targeted, measured optimization release, **not** a new GUI or a change in the machine-readable JSON v1 schema. The primary product remains the standalone Node.js CLI. The Obsidian plugin remains optional and separately packaged, with the existing `x-feed-scraper` plugin ID preserved.

## Improvements

- A conservative no-op fast path for unchanged source observations: only when the normalized observation, latest immutable revision hash, every active source claim/draft/evidence, and current evaluator result and identity all match exactly are redundant SQLite writes skipped. The engine **still runs the source adapters, processors and evaluators**, refreshes `last_seen`, retains the same duplicate accounting and advances the page checkpoint atomically. Legacy identity-collision guard cases keep the full processing path.
- Offline reprocessing reuses its query and evaluator and commits assessments in atomic groups of at most 100 entities instead of opening a separate SQLite transaction per entity. A failed evaluator preserves earlier complete batches and leaves the current incomplete batch uncommitted.
- Human reviews, provenance, per-observation versions, alerts, JSON/NDJSON export formats, and Obsidian output protections remain unchanged.
- Expanded regression tests for evaluator policy changes with unchanged source observations, missing historical revision repair, strict duplicate counts, saved human reviews and abort/failure while reevaluating.
- Release automation now publishes and **verifies** the next release and all three assets against the tested commit *before* deleting the previous GitHub Release. The final Releases list still contains exactly one entry; old Git tags and commits remain for auditability.

## Measured offline comparisons against 0.11

On the same GitHub Actions Linux runner (Node.js 22.16, independent synthetic SQLite databases), one measured comparison reported:

| Workload | v0.11 | v0.12 candidate | Gain |
| --- | ---: | ---: | ---: |
| First ingest of 1,800 records | 276.14 ms | 280.72 ms | Comparable; slight 1.7% overhead |
| Re-read 1,800 unchanged records | 242.90 ms | 123.30 ms | 1.97× faster |
| Re-read with one changed record | 226.24 ms | 99.50 ms | 2.27× faster |
| Reassess 2,400 stored records | 1000.74 ms | 170.69 ms | 5.86× faster |
| Reassess the same 2,400 records again | 972.46 ms | 155.46 ms | 6.26× faster |

Benchmarks use synthetic local JSON, not live RSS/MCP HTTP latency, so they are **not universal performance claims**. See [performance methodology](https://github.com/ibbuilds/source-scraper/blob/v0.12.0-beta.1/docs/performance.md).

We tested an additional bulk provenance export path, but **reverted it** after small JSON exports slowed down and larger exports improved only modestly. Preserving the simple, already-correct export behavior is preferable to adding complexity without reliable gains.

## Assets and installation

- **`source-scraper.mjs`** — the primary standalone executable bundle; Node.js >=22.16 required, no npm or Obsidian installation.
- `source-scraper-0.12.0.tgz` — locally installable npm tarball from GitHub; **not** published to the public npm registry.
- `obsidian-x-feed-scraper.zip` — separate **optional** Obsidian Community Plugin.

```sh
node source-scraper.mjs init --dir ./demo
node source-scraper.mjs run --config ./demo/project.json
node source-scraper.mjs export --config ./demo/project.json --out ./results.json
```

The starter runs entirely offline. Back up existing SQLite libraries before migrations.

## Explicit limitations

The account-personalized X **For You** feed still has no verified provider-authorized adapter. The owner's personal Obsidian vault/MCP has not been tested by this release workflow. Source-specific license/relevance scores remain evidence-based heuristics, and trusted local MCP/extensions still run with the user's OS privileges (not sandboxed).
